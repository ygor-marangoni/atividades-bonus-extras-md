# Origens e Evolução (1)

## Objetivo

Eu pesquisei uma linha do tempo resumida das principais técnicas de modelagem de software e procurei relacionar cada período aos problemas que essas técnicas ajudavam a resolver.

## Linha do tempo

| Período | Técnica ou marco | Exemplo notável |
|---|---|---|
| Décadas de 1960 e 1970 | diagramas de fluxo e análise estruturada | fluxogramas e DFDs para descrever processamento e movimentação de dados |
| Década de 1970 | modelo entidade-relacionamento | diagrama ER de Peter Chen para representar dados e relacionamentos |
| Década de 1980 | orientação a objetos | Booch, OMT e outros métodos para modelar classes e interações |
| Década de 1990 | UML | unificação de notações de análise e projeto orientado a objetos |
| Décadas de 2000 e 2010 | práticas ágeis, DDD e modelos leves | histórias de usuário, Event Storming e Context Mapping |
| Atualidade | modelos colaborativos e executáveis | C4 Model, DSLs, diagramas versionados e documentação como código |

## Recursos que eu utilizaria para aprofundar

Para entender a parte histórica, eu buscaria livros de engenharia de software e documentos mantidos pelos grupos responsáveis pelas notações. Para UML, a especificação da OMG é uma fonte técnica importante. Para DDD, o livro de Eric Evans e materiais de comunidades de modelagem ajudam a relacionar linguagem, contexto e regras de negócio. Para modelos contemporâneos, documentação de ferramentas como PlantUML e C4 Model permite observar exemplos reproduzíveis.

## Minha reflexão

Eu percebi que as técnicas não se substituíram por completo. Um DER ainda é útil quando eu preciso discutir dados; um diagrama de sequência ajuda quando meu problema é comportamento; e práticas de DDD ajudam quando a dificuldade está no significado das regras do negócio.
